## 1. TUI 工作模式

DeepSeek TUI 有 **3 种工作模式**，控制工具的执行权限。

### 模式对比

| 模式 | 快捷键 | 命令 | Shell | 文件写入 | 工具批准 | 适用场景 |
|------|--------|------|-------|---------|---------|---------|
| **Plan** (计划) | `Tab` | `/mode plan` | ❌ 禁用 | ❌ 禁用 | ❌ 禁用 | 思考、调查、制定计划 |
| **Agent** (代理) | `Tab` | `/mode agent` | ⚠️ 需批准 | ✅ 允许 | ⚠️ 需批准 | 日常开发（默认） |
| **YOLO** (自由) | `Tab` | `/mode yolo` | ✅ 允许 | ✅ 允许 | ✅ 自动 | 可信仓库，高效开发 |

---

### 切换模式的 3 种方法

#### 方法 1: 快捷键（最快）

```
Tab         # 循环切换: Plan → Agent → YOLO → Plan
Shift+Tab   # 循环切换推理强度: off → high → max → off
```

#### 方法 2: Slash 命令

```bash
# 打开模式选择器
/mode

# 直接切换到指定模式
/mode plan      # Plan 模式
/mode agent     # Agent 模式
/mode yolo      # YOLO 模式

# 使用数字快捷方式
/mode 1         # = Plan 模式
/mode 2         # = Agent 模式
/mode 3         # = YOLO 模式
```

#### 方法 3: 启动参数

```bash
# 启动时直接进入 YOLO 模式
deepseek --yolo

# 启动时指定模式（如果支持）
deepseek --mode agent
```

---

### 模式详细说明

#### Plan 模式（计划模式）🔍

**特点**：
- ✅ 只读工具可用（文件读取、代码搜索、grep 等）
- ❌ Shell 命令禁用
- ❌ 文件写入禁用
- ❌ 代码修改禁用

**适用场景**：
- 理解代码结构
- 调查问题原因
- 制定开发计划
- 代码审查（只读）

**示例**：
```
用户: "帮我分析一下这个项目的架构"
AI:  [使用 read_file, grep_code 等只读工具]
      "这个项目采用了 MVC 架构，主要模块包括..."
```

---

#### Agent 模式（代理模式）🤖

**特点**：
- ✅ 所有工具可用
- ⚠️ Shell 命令需要批准
- ✅ 文件写入允许
- ⚠️ 付费工具需要批准

**适用场景**：
- 日常开发（默认模式）
- 需要 AI 辅助编程
- 需要执行测试
- 安全的代码修改

**示例**：
```
用户: "帮我创建一个用户登录组件"
AI:  [请求批准执行 write_file]
      "我将创建 login.tsx，是否继续？ [y/n]"
用户: y
AI:   [创建文件]
      "已创建 login.tsx"
```

---

#### YOLO 模式（自由模式）⚡

**特点**：
- ✅ 所有工具自动批准
- ✅ Shell 命令自动执行
- ✅ 文件写入自动执行
- ⚠️ **仅在可信仓库使用！**

**适用场景**：
- 个人项目
- 测试环境
- 快速原型开发
- 完全信任 AI 的场景

**示例**：
```
用户: "重构整个项目的错误处理"
AI:   [自动执行所有操作，无需确认]
      "已完成重构，修改了 15 个文件"
```

## 2. 批准模式

批准模式控制 **工具执行时是否需要用户确认**。

### 批准模式对比

| 模式 | 命令 | 说明 | 适用场景 |
|------|------|------|---------|
| **suggest** (建议) | `/config approval_mode suggest` | 非安全工具需要确认 | 日常使用（默认） |
| **auto** (自动) | `/config approval_mode auto` | 所有工具自动批准 | 高效开发 |
| **never** (从不) | `/config approval_mode never` | 阻止需要批准的工具 | 只读场景 |

---

### 设置批准模式

#### 方法 1: 使用 /config 命令

```bash
# 查看当前配置
/config
# 找到 approval_mode 行，编辑它

# 直接设置
/config approval_mode auto      # 自动批准
/config approval_mode suggest   # 建议批准（默认）
/config approval_mode never     # 从不执行
```

#### 方法 2: 使用别名

```bash
# 这些等价于 suggest
/config approval_mode on-request
/config approval_mode untrusted

# 这些等价于 never
/config approval_mode deny
/config approval_mode denied
```

---

### 批准模式与 TUI 模式的关系

| TUI 模式 | approval_mode=suggest | approval_mode=auto | approval_mode=never |
|---------|----------------------|-------------------|---------------------|
| **Plan** | 只读工具可用 | 只读工具可用 | 只读工具可用 |
| **Agent** | 非安全工具需确认 | 所有工具自动执行 | 阻止非安全工具 |
| **YOLO** | 自动设为 auto | 所有工具自动执行 | 自动设为 auto |

**重要**：
- YOLO 模式会**强制**使用 `auto` 批准，忽略您的设置
- 退出 YOLO 模式后，会**恢复**之前的批准模式设置

## 3. 常用命令速查

### 模式相关命令

```bash
# 查看/切换 TUI 模式
/mode                   # 打开模式选择器
/mode plan              # 切换到 Plan
/mode agent             # 切换到 Agent
/mode yolo              # 切换到 YOLO
/mode 1/2/3             # 数字快捷方式

# 查看/设置批准模式
/config                 # 查看所有配置
/config approval_mode auto      # 自动批准
/config approval_mode suggest   # 建议批准
/config approval_mode never     # 从不执行

# 信任模式（允许访问工作区外文件）
/trust                  # 切换信任模式
```

### 其他常用命令

```bash
# 会话管理
/sessions               # 查看会话列表
/resume <id>            # 恢复会话

# 配置
/config                 # 查看所有/编辑配置
/config locale zh-Hans  # 设置中文
/config theme dark      # 设置暗色主题

# 工具控制
/compact                # 压缩上下文
/queue                  # 查看队列

# 帮助
/help                   # 查看帮助
```

## 4. 使用场景推荐

### 场景 1: 学习/理解代码（只读）

```bash
# 推荐配置
/mode plan
# Plan 模式自动禁用所有写入工具
```

**工作流**：
```
1. /mode plan
2. "帮我分析这个项目的架构"
3. "找出所有 API 端点"
4. "解释认证流程"
```

---

### 场景 2: 日常开发（安全优先）

```bash
# 推荐配置
/mode agent
/config approval_mode suggest
```

**工作流**：
```
1. /mode agent
2. "创建一个用户注册组件"
3. AI 请求批准 → 按 y 确认
4. "添加表单验证"
5. AI 请求批准 → 按 y 确认
```

---

### 场景 3: 高效开发（自动批准）

```bash
# 推荐配置
/mode agent
/config approval_mode auto
```

**工作流**：
```
1. /mode agent
2. /config approval_mode auto
3. "重构错误处理模块"
4. AI 自动执行，无需确认
5. "运行测试"
6. AI 自动执行测试
```

---

### 场景 4: 个人项目（完全自由）

```bash
# 推荐配置
/mode yolo
# 自动启用所有权限和自动批准
```

**工作流**：
```
1. /mode yolo
2. "实现完整的用户系统"
3. AI 自动创建文件、运行测试、提交代码
4. 完成后检查结果
```

---

### 场景 5: 代码审查（只读 + 严格）

```bash
# 推荐配置
/mode plan
/config approval_mode never
```

**工作流**：
```
1. /mode plan
2. /config approval_mode never
3. "审查这段代码的安全性"
4. AI 只能读取，不能修改
```

## 🎯 快速决策树

```
开始
  │
  ├─ 只需要读取代码？
  │   └─ YES → /mode plan
  │
  ├─ 需要修改代码？
  │   │
  │   ├─ 想要每次确认？
  │   │   └─ YES → /mode agent + /config approval_mode suggest
  │   │
  │   ├─ 想要自动执行？
  │   │   └─ YES → /mode agent + /config approval_mode auto
  │   │
  │   └─ 完全信任 AI？
  │       └─ YES → /mode yolo
  │
  └─ 不允许任何修改？
      └─ YES → /mode plan + /config approval_mode never
```

---

## ⚠️ 注意事项

1. **YOLO 模式危险**：会自动执行所有操作，包括删除文件。仅在可信仓库使用！

2. **批准模式是会话级**：关闭程序后会重置，需要重新设置。

3. **YOLO 模式会覆盖批准模式**：进入 YOLO 时自动设为 `auto`，退出时恢复。

4. **Plan 模式最安全**：无论如何设置，Plan 模式都禁用所有写入工具。

5. **使用 `/config` 而非 `/set`**：`/set` 命令已废弃。
