## 1. 权限系统概述

DeepSeek TUI 有**两层权限控制**：

### 第一层：TUI 模式（决定哪些工具可用）

| 模式 | exec_shell | write_file | agent_open | 说明 |
|------|-----------|-----------|-----------|------|
| **Plan** | ❌ 禁用 | ❌ 禁用 | ❌ 禁用 | 只读调查 |
| **Agent** | ⚠️ 可用 | ✅ 可用 | ⚠️ 可用 | 需要批准 |
| **YOLO** | ✅ 可用 | ✅ 可用 | ✅ 可用 | 自动批准 |

### 第二层：批准模式（决定是否需要确认）

| 批准模式 | 说明 | 适用场景 |
|---------|------|---------|
| **suggest** | 危险工具需要确认 | 安全优先（默认） |
| **auto** | 所有工具自动执行 | 高效开发 |
| **never** | 阻止危险工具 | 只读场景 |

## 2. 三大权限级别

### 2.1 exec_shell（执行 Shell 命令）

**功能**：允许 AI 执行系统命令（如 `ls`, `grep`, `cargo build` 等）

**风险等级**：🔴 高（可能执行破坏性命令）

**在 Plan 模式**：❌ **强制禁用**，无法通过 approval_mode 覆盖

**在 Agent 模式**：
- `approval_mode=suggest` → 每次执行前需要您确认
- `approval_mode=auto` → 自动执行，无需确认
- `approval_mode=never` → 禁止执行

**在 YOLO 模式**：✅ 自动执行

---

### 2.2 write_file（写入文件）

**功能**：允许 AI 创建、修改、删除文件

**风险等级**：🟡 中（可能误改代码）

**在 Plan 模式**：❌ **强制禁用**

**在 Agent 模式**：
- ✅ **始终允许**（不需要批准）
- 这是 Agent 模式的核心功能

**在 YOLO 模式**：✅ 自动执行

---

### 2.3 agent_open（打开子智能体会话）

**功能**：允许 AI 创建独立的子智能体执行任务

**风险等级**：🟡 中（消耗 Token 和时间）

**在 Plan 模式**：❌ **强制禁用**

**在 Agent 模式**：
- `approval_mode=suggest` → 需要您确认
- `approval_mode=auto` → 自动创建
- `approval_mode=never` → 禁止创建

**在 YOLO 模式**：✅ 自动创建

## 3. 如何授予权限

### 场景 1: 启用所有权限（推荐用于开发）

```bash
# 步骤 1: 切换到 Agent 模式
/mode agent

# 步骤 2: 设置自动批准
/config approval_mode auto
```

**效果**：
- ✅ exec_shell: 可用，自动执行
- ✅ write_file: 可用，自动执行
- ✅ agent_open: 可用，自动执行

---

### 场景 2: 启用权限但需要确认（安全模式）

```bash
# 步骤 1: 切换到 Agent 模式
/mode agent

# 步骤 2: 使用默认批准模式（suggest）
# 无需额外设置，默认就是 suggest
```

**效果**：
- ⚠️ exec_shell: 可用，每次需要确认
- ✅ write_file: 可用，自动执行
- ⚠️ agent_open: 可用，每次需要确认

---

### 场景 3: 完全自由（个人项目）

```bash
# 一步到位：切换到 YOLO 模式
/mode yolo
```

**效果**：
- ✅ exec_shell: 可用，自动执行
- ✅ write_file: 可用，自动执行
- ✅ agent_open: 可用，自动执行

**注意**：YOLO 模式会**自动**设置 `approval_mode=auto`

---

### 场景 4: 只读调查（代码审查）

```bash
# 切换到 Plan 模式
/mode plan
```

**效果**：
- ❌ exec_shell: 禁用
- ❌ write_file: 禁用
- ❌ agent_open: 禁用

## 4. 常见问题解决

### 问题 1: 为什么 `/config approval_mode auto` 不生效？

**原因**：您可能仍在 **Plan 模式**

**解决**：
```bash
# 先切换到 Agent 或 YOLO 模式
/mode agent
# 或
/mode yolo

# 然后再设置批准模式
/config approval_mode auto
```

---

### 问题 2: 如何确认当前模式？

**方法 1**: 查看顶部状态栏

```
agent · qwen3.5-9b-deepseek-v4-flash@q6_k · ...
  ↑
  这里显示当前模式
```

**方法 2**: 使用命令查看

```bash
/config
# 查看 mode 行
```

---

### 问题 3: exec_shell 仍然被拒绝？

**检查清单**：

1. ✅ 确认当前不是 Plan 模式
   ```bash
   /mode agent
   ```

2. ✅ 确认 approval_mode 不是 never
   ```bash
   /config approval_mode auto
   ```

3. ✅ 如果是 YOLO 模式，应该自动生效
   ```bash
   /mode yolo
   ```

---

### 问题 4: AI 说"工具不可用"怎么办？

**典型错误**：
```
Failed to authorize tool execution: Tool 'exec_shell' is unavailable in Plan mode
```

**解决方法**：
```bash
# 必须由您手动切换模式（AI 无法自行切换）
/mode agent

# 或
/mode yolo
```

**重要**：Plan 模式下，AI **无法**通过命令自行切换模式，必须由**您手动输入**。

---

### 问题 5: 如何临时允许一个命令？

**场景**：使用 `approval_mode=suggest`，AI 请求执行命令

**操作**：
```
# AI 显示：
执行: cargo build
是否继续？[y/n/a/d]

# 您的选择：
y  → 允许这一次
a  → 允许所有（本次会话）
n  → 拒绝
d  → 拒绝并记住（本次会话）
```

## 5. 安全建议

### 5.1 权限使用原则

| 原则 | 说明 |
|------|------|
| **最小权限** | 只授予必要的权限 |
| **逐步放开** | 从 suggest → auto → yolo |
| **环境隔离** | 在测试环境使用 YOLO |
| **代码审查** | 重要修改后检查 diff |

---

### 5.2 推荐配置

#### 新手用户
```bash
/mode agent
/config approval_mode suggest
# 每次确认，最安全
```

#### 日常开发
```bash
/mode agent
/config approval_mode auto
# 自动执行，平衡效率和安全
```

#### 个人项目
```bash
/mode yolo
# 完全自由，最高效率
```

#### 代码审查
```bash
/mode plan
# 只读，最安全
```

---

### 5.3 危险命令防护

即使使用 `approval_mode=auto` 或 YOLO 模式，以下命令仍建议**手动执行**：

```bash
# ⚠️ 危险命令示例
rm -rf /          # 删除所有文件
sudo rm -rf /*    # 删除系统文件
format C:         # 格式化硬盘
# ... 等破坏性命令
```

**建议**：在 `.gitignore` 或项目配置中设置**命令黑名单**。

# 设置批准模式
/config approval_mode suggest   # 确认

| 您的需求 | 命令 |
|---------|------|
| **我要安全** | `/mode agent` |
| **我要效率** | `/mode agent` + `/config approval_mode auto` |
| **我要自由** | `/mode yolo` |
| **我要只读** | `/mode plan` |

---

## ⚠️ 重要提醒

1. **Plan 模式是硬性限制**：无法通过 approval_mode 覆盖
2. **切换模式必须手动**：AI 在 Plan 模式下无法自行切换
3. **YOLO 模式很强大**：仅在可信仓库使用
4. **定期审查修改**：即使自动执行，也要检查结果

---

> **提示**：不确定时，从 `/mode agent` + `suggest` 开始，逐步放开权限。
